# libSceContentExport

## change [Content export sessions]

- [Content export sessions](../../../core/libs/prx/libSceContentExport/Export.cpp): the host has no media library, so the remaining file export entry points validate the export session before calling NotImplemented_nid_no_patch; sceContentExportFromData and sceContentExportFromDataWithThumbnail write their chunks to temporary files instead, as their own entries describe. Session allocation does not reproduce guest allocator calls, worker creation or failure paths. Initialization and session lookup throw for some invalid inputs instead of reproducing console error precedence. Session IDs use the lowest free slot in 0–9; exhaustion, termination with live sessions and cancellation return confirmed errors.

## add Functional

- [sceContentExportValidateContents, sceContentExportGetProgress and sceContentExportFromFileWithTitleIdList](../../../core/libs/prx/libSceContentExport/Export.cpp) (libSceContentExport) - local checks follow a firmware 9.20 reading (#25863); past them each call reaches the content-management service and calls NotImplemented_nid_no_patch. The title-id export throws for malformed JSON (parser codes unread) and for elements whose rendered length is unsettled; another session holding the same file can't happen here, so `0x809D301A` comes only from source and thumbnail being one file. Not reproduced: a running export's progress. GetProgress throws after sceContentExportFromData. `param+0x101` is taken to be `comment`. Unreadable parameters or strings return `0x809D3016`.

- [sceContentExportFromDataWithThumbnail](../../../core/libs/prx/libSceContentExport/Export.cpp) (libSceContentExport) - follows the firmware 9.20 reading (#25863): past its checks it writes the content and then the thumbnail through their callbacks to `/av_contents/content_tmp/sce_cmgcnt<id>.<subtype>` and `sce_cmgthm<id>.jpg`, returns `0x809D3016` when either byte count differs from its length, and ends the session on every result past the callback-parameter checks, so GetProgress then gives 100 (`0x809D3002` below SDK 6.00). The content-management service is not modeled: the content file's path is returned in place of the service's path, and the TRC notification and login-user query are skipped. Write errors and callback results map as in sceContentExportFromData, and a running export's progress is not tracked. Unreadable parameters, callback parameters or output paths return `0x809D3016`, and an unreadable thumbnail type `0x809D3019`.
